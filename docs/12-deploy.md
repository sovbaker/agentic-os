# Развёртывание и эксплуатация

Пункт 8 критического пути (`11-board-review.md`). Документ рабочий:
по нему поднимается сервер с нуля и по нему же чинится, когда он лёг.

Размер решения выбран под бету на 20–30 человек: одна машина, один
процесс API с воркером внутри, одна база. Это не «пока сойдёт» — на этих
числах ничего другого не нужно, а всё, что сложнее, стоит денег и
внимания уже сегодня, а окупается на порядок дальше.

---

## 1. Что нужно до начала

| Что | Зачем | Кто даёт |
| --- | --- | --- |
| VPS, 2 vCPU / 4 ГБ / 40 ГБ, Docker | Всё крутится здесь | Любой провайдер, доступный из РФ |
| Домен и A-запись на IP машины | Без домена нет сертификата, без сертификата нет приложения | Регистратор |
| Ключ Anthropic | Иначе продукт работает на правилах | console.anthropic.com |
| Ключ поискового провайдера | Обогащение задач | Brave / Serper / любой JSON-API |

**HTTPS не опция.** App Transport Security в iOS по умолчанию запрещает
обычный HTTP. Сборка, собранная на `http://…`, не увидит сервер вовсе —
и выглядеть это будет как «приложение не работает», а не как «нет
сертификата».

## 2. Первый запуск

```bash
git clone <repo> && cd agentic-os/deploy
cp .env.example .env && $EDITOR .env      # заполнить всё, что пустое
docker compose up -d --build
docker compose logs -f api                # ждём «api запущен»
```

Секреты генерируются так:

```bash
openssl rand -base64 24   # POSTGRES_PASSWORD
openssl rand -hex 32      # INBOUND_SECRET, METRICS_TOKEN
```

Миграции применяются самим API на старте — отдельного шага нет. В логе
это видно строками `миграция применена: NNN_*.sql`.

### Проверка после запуска

```bash
curl -sS https://$API_DOMAIN/health                    # {"ok":true,"db":true}
curl -sS -X POST https://$API_DOMAIN/v1/inbound/email  # 401 с секретом, 503 без
curl -sS https://$API_DOMAIN/v1/metrics                # 401 без токена
```

Проверяется здесь ровно одно: что на второй и третьей строках **не 200**.
Какой именно отказ — 401 (секрет задан, заголовка нет) или 503 (секрет не
задан, ручка выключена) — зависит от того, заполнил ли ты `.env`. А вот
`200` означает открытую ручку в интернет, и это единственный ответ,
после которого дальше идти нельзя.

В логе старта смотрим три поля:

- `vectorSearch: true` — pgvector поднялся, семантический поиск включён.
  `false` означает, что миграция 002 пропущена и retrieval работает
  только структурно: продукт жив, но хуже;
- `llm: anthropic` — ключ подхватился. `rule` значит, что вся
  интеллектуальная часть отключена, а внешне всё выглядит рабочим;
- `воркер запущен` — иначе задачи не поедут дальше первого шага.

## 3. Обновление

```bash
cd agentic-os && git pull
cd deploy && docker compose up -d --build api
```

Простой на время пересборки — секунды. Задачи это переживают: аренда
шага истекает, и следующий запуск подхватывает их с того же места. Ради
этого аренда и делалась.

### Откат

```bash
git checkout <прошлый-коммит>
docker compose up -d --build api
```

Миграции вперёд-совместимы (`ADD COLUMN IF NOT EXISTS`), поэтому откат
кода не требует отката схемы. Это верно ровно до первой миграции,
которая что-то удаляет или сужает; такую нужно делать в два релиза:
сначала перестать писать, потом, отдельным релизом, удалить.

## 4. Бэкапы

Контейнер `backup` раз в сутки кладёт сжатый дамп в том `backups` и
удаляет всё старше `BACKUP_KEEP_DAYS`.

```bash
docker compose exec backup ls -lh /backups           # что есть
docker compose logs backup | tail -5                 # когда последний
```

**Дамп нужно вывозить с машины.** Бэкап, лежащий на том же диске, что и
база, защищает от «удалил не ту строку» и не защищает ни от чего
другого. Раз в сутки с ноутбука или из другого места:

```bash
scp -r server:/var/lib/docker/volumes/agentic-os_backups/_data/ ~/backups/
```

### Учебное восстановление

Делать до беты, а потом раз в месяц. Бэкап, из которого ни разу не
восстанавливались, бэкапом не является.

```bash
docker compose exec db createdb -U agentic restore_test
gunzip -c agentic_os-<штамп>.sql.gz | \
  docker compose exec -T db psql -U agentic -d restore_test
docker compose exec db psql -U agentic -d restore_test \
  -c "SELECT (SELECT count(*) FROM app_user) AS users,
             (SELECT count(*) FROM fact)     AS facts,
             (SELECT count(*) FROM job)      AS jobs,
             (SELECT count(*) FROM audit_log) AS audit"
docker compose exec db dropdb -U agentic restore_test
```

Смотрим не на «команда отработала», а на четыре числа и сверяем их с
боевой базой. Восстановление, потерявшее `audit_log`, теряет вместе с
ним возможность что-либо отменить — а это единственное, что мы обещаем
пользователю про необратимость.

## 5. Секреты и их смена

| Переменная | Что ломается при утечке | Как менять |
| --- | --- | --- |
| `ANTHROPIC_API_KEY` | Деньги | Новый ключ в консоли, старый отозвать |
| `INBOUND_SECRET` | Кто угодно пишет в чужой карантин | Сменить одновременно с настройкой у почтового провайдера |
| `METRICS_TOKEN` | Утекает продуктовая аналитика по всем | Сменить и обновить там, откуда снимаются метрики |
| `POSTGRES_PASSWORD` | Всё | `ALTER USER` + правка `.env` + перезапуск |

Токены устройств не сменяемы: у них нет владельца, которого можно
переспросить. Компрометация базы = перевыпуск всех токенов, то есть
повторная регистрация у всех. Это осознанная цена регистрации без
логина; полноценный вход снимает её и стоит в очереди отдельно.

## 6. Что смотреть каждый день

```bash
curl -sS -H "x-metrics-token: $METRICS_TOKEN" https://$API_DOMAIN/v1/metrics | jq
```

Три числа, по которым видно состояние продукта, а не сервера:

- **TCFY** — задач закрыто целиком. Падает — продукт перестал доводить
  до конца, и это важнее любой технической метрики;
- **economy.p90** — стоимость задачи по девяностому перцентилю. Растёт —
  ломается юнит-экономика; потолок `TASK_BUDGET_RUB` = 25 ₽;
- **economy.cacheHitRate** — доля чтения из кэша. Падение вдвое обычно
  значит, что персональный контекст перестал быть стабильным между
  ходами, и счёт вырастет соответственно.

Технические сигналы (в логе):

- `лимит частоты` — кто-то упёрся в лимит. Единичные записи нормальны,
  поток от одного ключа означает цикл в клиенте;
- `вызов модели не удался, работаю по правилам` — **самая опасная
  строка в логе**: продукт продолжает отвечать, и снаружи всё хорошо;
- `бэкап не удался` — идти чинить сегодня, а не когда понадобится.

## 7. Известные ограничения этой конфигурации

Не недостатки, а сознательные границы. Каждая снимается отдельной
работой, и делать её раньше, чем упрётся, — трата.

1. **Одна машина.** Падает — падает всё. Приемлемо для беты, неприемлемо
   для платящих.
2. **Лимит частоты в памяти процесса.** При нескольких инстансах
   счётчики разъедутся; переезд в Redis меняет только `Window`
   в `apps/api/src/http/limits.ts`.
3. **Воркер в процессе API.** Общается с остальным кодом только через
   базу, поэтому вынос — механическая операция.
4. **Нет алертов.** Метрики снимаются руками. До беты этого хватает,
   на платящих — нет.
5. **Дамп раз в сутки.** Потеря до 24 часов данных при отказе диска.
   WAL-архивирование или управляемая база убирают это.
