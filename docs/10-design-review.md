# Дизайн-ревью и переработка

Ревью проведено по методу Impeccable (`/impeccable critique`) двумя изолированными
ассессментами: дизайн-ревью и детерминированные замеры в браузере. Краски
и типографика — по taste-skill, движение и отклик — по emil-design-eng.

Полный отчёт: `.impeccable/critique/2026-08-09T22-45-00Z__apps-mobile.md`.

---

## Что показало ревью

**19/40 по эвристикам Нильсена.** Когнитивная нагрузка — 5 провалов из 8.
Вердикт по специфичности: **задизайненная кожа поверх незадизайненной модели
взаимодействия**. Авторскими были ровно две вещи — русский копирайтинг и
решение вынести цвет и отступы из досягаемости модели. Всё остальное —
универсальный мобильный UI-kit, который подставляется в любой список дел.

### Детектор дал ложно-чистый результат, и это доказано

Сканирование исходников вернуло ноль находок. Ассессмент B собрал
положительный контроль: два семантически идентичных файла — в `.css`
детектор нашёл четыре нарушения, в `.tsx` со `StyleSheet.create` — ноль.
Правила написаны под веб-CSS, объекты стилей React Native им не видны.
**Покрытие этой кодовой базы правилами детектора — нулевое.** «Чисто»
здесь означало слепое пятно, а не справку о здоровье; настоящие числа дал
браузерный прогон.

### Что нашли замеры, а не глаза

| Замер | Было |
|---|---|
| Контраст стрелки отправки **в состоянии по умолчанию** | **1.98:1** светлая, 2.16:1 тёмная |
| Цели касания меньше 44pt на главном экране | **9 из 13** |
| Горизонтальное переполнение на 320px | **25px на каждом экране** |
| Переходов и анимаций во всех 12 съёмках | **0** |
| Интерлиньяж не задан | на **75%** текстовых узлов |
| `textMuted` на фоне страницы | 4.40:1 — провал AA на половине интерфейса |

Стрелка отправки — показательный случай: собственный цвет кнопки проходил
(5.18:1), губила его `opacity: 0.4` на обёртке, а это состояние по умолчанию
на каждой загрузке любого экрана. Главное действие продукта было почти
невидимым, и ревью кода этого не увидело.

## Что переделано

Визуальный мир пока не выбран — переработано то, что от него не зависит.

### Реестр перестал быть UI-китом

Появились четыре компонента про то единственное, чем продукт отличается от
списка дел. Ось у всех одна — **чей сейчас ход**:

| Компонент | Что говорит |
|---|---|
| `agentDid` | «Записал тебя на подачу» — время и честный срок отмены |
| `agentIntent` | «Собираюсь отправить анкету»: было → станет, **что уйдёт наружу**, и строка «пока не подтвердишь — ничего не отправляю» |
| `awaiting` | «Жду ответа: визовый центр» — с какого числа, обычный срок, «пнуть» |
| `sourceStamp` | откуда факт и насколько уверен — двумя независимыми каналами |

Три состояния из четырёх намеренно ахроматичны. Цвет остаётся ровно одному —
«твой ход», — и поэтому означает что-то, а не украшает.

Под них добавлены данные, без которых компоненты печатали бы выдуманную
точность: срок обратимости у записи журнала, «жду от кого и с какого числа»
у задачи, срок самой задачи (миграция `007_moves.sql`).

### Эмодзи убраны структурно, а не по договорённости

`icon` принимал `glyph: string`, и сервер присылал эмодзи. Теперь принимает
`name` из закрытого перечисления `IconName`, а рисунок живёт в бинаре:
подсунуть произвольный символ **физически нельзя**. 26 знаков нарисованы
геометрией View — без нативных зависимостей, ценой словаря простых форм.

### Возврат

`screen.props.title` объявлен на каждой спеке и выбрасывался рендерером.
Отсюда не было ни шапки, ни места для возврата, а `setSpec(null)` жил внутри
`submit()` — то есть уйти с экрана можно было только уничтожив свою работу.
Появился стек экранов, шапка с возвратом и открытие сохранённой мини-аппы по
идентификатору.

### Лента перестала врать

Карточка вела в серый баннер с текстом, который человек и так читает.
Теперь карточка открывает свою мини-аппу, а карточка без назначения **не
нажимается вовсе** — фальшивая нажимаемость хуже её отсутствия.

### Отклик и движение

Нажатие выражалось только прозрачностью — это «элемент выключается», а не
«интерфейс услышал палец». Единственный способ сделать что-либо нажимаемым —
компонент `Tap`: сжатие на 3% за 90 мс, спокойный возврат за 160, минимум
44pt, роль и состояние для VoiceOver. Забыть их больше нельзя: они живут
в одном месте.

### Доступность

Был один `accessibilityLabel` на весь клиент и реестр. Теперь роль, подпись
и состояние есть у каждого интерактивного элемента; чек-лист объявляется
флажком с состоянием, а не статическим текстом. Проверяется прогоном:
**0 целей меньше 44pt, 0 переполнения на 320px**.

### Подтверждение знает о тяжести последствий

«Удалить всё безвозвратно» и «Отправить сообщение мастеру?» получали
одинаковое оранжевое «Подтверждаю». Теперь у листа есть тон: опасное —
красным контуром, конкретным глаголом и с отменой в доминирующей позиции,
лист модальный с затемнением, и он один на весь продукт (дубль в оболочке
удалён).

### Закрытие задачи выглядит закрытием

У кнопки появились состояния `pending` и `done`. План со сроком уже ставит
напоминание сам — и раньше кнопка оставалась активной, приглашая создать
**второе** напоминание без единого признака, что первое есть.

### Первый запуск показывает одно решение

Было девять вариантов с одинаковым оформлением: три примера фраз выглядели
ровно как шесть чипов архетипов. Всё служебное ушло за одно раскрытие,
архетипы появляются после первой закрытой задачи — когда у человека есть
причина помочь себя понять.

### Типографика и токены

| | Было | Стало |
|---|---|---|
| Шкала | 26/19/16/15/13, шаги 1.19 / 1.13 / 1.07 | 30/22/17/14/12, шаги 1.36 / 1.29 / 1.21 |

| Числа в колонке | обычные цифры | табличные |
| `textMuted` | 4.40:1 | **6.14:1** |

Тёмный `danger` показателен: первая попытка (`#F04438`) чинила иерархию и
ломала читаемость — 4.04:1. Считать надо оба числа сразу.

## Найденные дефекты

| Что | Почему это важно |
|---|---|
| `grid` схлопывался в колонку при `gap ≥ 4` | проценты складывались с пиксельным зазором; экран приватности рендерился четырьмя полосами вместо 2×2, а фикстура на `gap: 2` дефект не показывала |
| `keyValue` принимает список пар, а не `label`/`value` | спека проходила валидатор и приезжала пустым блоком |
| `privacy_request` уносилась каскадом вместе с пользователем | доказательства удаления не оставалось никогда |
| Шапка и заголовок звали экран по-разному | «Документы: Италия» против «Виза: Италия» на одном экране |
| Тип параметра внутри `CASE` не выводится | `could not determine data type of parameter $9` — тот же класс ошибки, что и с дробным весом в S1 |
| `textField.onSubmit` писал ответ в мешок, который никто не читает | ассистент задавал единственный уточняющий вопрос и выбрасывал ответ |

## Проверки

```bash
npm run typecheck                        # 5 пакетов
npm test                                 # 98 тестов
npm run build:web && npm run verify:ui   # браузер, светлая и тёмная темы
```

Браузерный прогон теперь проверяет числами то, что раньше проверялось
глазами: все цели касания ≥44pt, ноль переполнения на 320px, сетка не
схлопывается, шапка и возврат работают, действие агента показано
выполненным и не приглашает продублировать себя.

## Что осталось за выбором визуального мира

Панель из четырёх независимых направлений отработана, победитель —
«Оттиск» (мир бумаги и печати, где вся графика отвечает на вопрос «чей
сейчас ход»), альтернативы — «Диспетчерская» и «Дело №». Выбор за тобой;
он определяет палитру, гарнитуры, форму и авторский момент движения, но не
трогает ничего из перечисленного выше.
