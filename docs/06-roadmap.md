# Дорожная карта: 12 недель до проверяемого продукта

Допущение: команда 2–4 человека. При меньшей команде растягивается срок, но **не меняется порядок** — он подобран так, чтобы каждая гипотеза проверялась как можно раньше и дешевле.

---

## Фаза 0 — Фундамент (недели 1–2)

**Цель:** сквозной контур «сказал → получил экран» работает end-to-end на одном захардкоженном сценарии.

- Настройка Expo + `expo-dev-client` + EAS Build + TestFlight — **на первой неделе**, не позже. Оставленное на потом, это встанет поперёк релиза.
- `packages/contracts`: UISpec, Job, Entity/Fact, манифест инструмента — общие для клиента и сервера.
- Реестр компонентов v0: 15 базовых, рендерер, скриншот-тесты.
- BFF, авторизация, SSE-стриминг.
- Postgres + pgvector, базовые таблицы.
- Наблюдаемость с первого дня: OTel + Langfuse.

**Готово, когда:** голосом сказал фразу → на телефоне отрендерился экран из серверного UISpec.

---

## Фаза 1 — Мозг (недели 3–5)

**Цель:** агент реально закрывает задачи из одного семейства и не теряет их при перезапуске.

- Оркестратор: роутер → планировщик → исполнители → критик.
- Движок задач: персистентные автоматы, ретраи, идемпотентность, таймеры, компенсации.
- Инструменты v0: веб-поиск и исследование, календарь (чтение/запись), время, погода.
- Life graph v0: сущности, факты, провенанс, битемпоральность, гибридный retrieval.
- Экстрактор фактов из диалога + **карантинный экстрактор** для недоверенного контента.
- Классы прав, аудит, отмена.
- Golden set 50 запросов + реплей трасс.

**Готово, когда:** «Оформить визу в Италию к октябрю» проходит целиком, переживает рестарт сервиса, и в графе появляются осмысленные факты.

> 🚦 **Гейт G1 (конец недели 5).** Если task success rate < 60% на golden set — останавливаемся и чиним планировщик. Дальше без этого идти нельзя: всё последующее строится на предположении, что задачи закрываются.

---

## Фаза 2 — Интерфейс (недели 6–7)

**Цель:** мини-аппы как переиспользуемые артефакты, а не одноразовые экраны.

- Компилятор мини-апп: генерация → валидация → repair loop → реестр.
- Реестр компонентов до 35–45.
- Каталог: 8 готовых мини-апп по клину.
- Параметризация из life graph.
- Веб-рендер того же UISpec (контур шаринга).
- «Мои аппы», версионирование, состояние и история.

**Готово, когда:** ≥95% сгенерированных UISpec валидны с первой попытки, открытие существующей аппы ≤200 мс.

> 🚦 **Гейт G2 (конец недели 7).** A/B: мини-аппа против текстового ответа на одинаковых задачах. Если разница по завершению задач < 20 п.п. — **гипотеза H2 не подтвердилась**, и генеративный UI надо понижать в приоритете, а не докручивать. Это самый важный гейт проекта: он проверяет центральную ставку.

---

## Фаза 3 — Привычка (недели 8–9)

**Цель:** продукт напоминает о себе сам и накапливает ценность.

- Лента «Сегодня» как главный экран.
- Движок проактивности: триггеры, политика уместности, бюджет ≤3/день, обучение на реакции.
- Push-уведомления, утренний бриф.
- Коннекторы: почта (чтение) с извлечением фактов, контакты.
- Онбординг целиком по `05-cold-start-lifegraph.md`: ноль вопросов → импорт → «Карта твоей жизни» → архетипы.
- Ассистированная передача: deep links с предзаполнением.

**Готово, когда:** реакция на проактивные пуши ≥35%, активация ≥60%.

---

## Фаза 4 — Закрытая бета (недели 10–12)

**Цель:** 50 реальных пользователей и честный ответ по гипотезам.

- MCP-клиент с allowlist.
- Оптимизация стоимости: роутинг моделей, кэш промптов, каталог вместо генерации.
- Лимиты, бюджеты, экран приватности, экспорт и удаление данных.
- Шаринг мини-апп по ссылке.
- Полный набор эвалов и еженедельный разбор трасс.
- 50 пользователей из целевого сегмента, еженедельные интервью.

> 🚦 **Гейт G3 (конец недели 12).** Смотрим на H1/H2/H3 из спеки:
> - TCFY (медиана) ≥ 3 — идём дальше.
> - 1.5–3 — есть ценность, но не там, где думали: пересобрать клин, не архитектуру.
> - < 1.5 — гипотеза о ценности не подтвердилась; менять сегмент или продукт.

## Что идёт параллельно, но вне продуктовой сборки

**`research/emulator`** — 1 человек, не раньше недели 6, в вебе, за флагом:

1. redroid на ARM-сервере, персистентные тома, снапшоты, замер реальной стоимости хранения на пользователя.
2. Управление через ADB + дерево доступности; vision только как fallback.
3. Три нефинансовых флоу: запись, заказ, оформление.
4. Обучение с демонстрации: запись → синтез параметризованной процедуры → верификация в песочнице.

**Гейт для перевода в продукт:** ≥85% успеха на трёх выученных флоу, ≤30 ₽ за прогон, медианное время ≤90 с, посчитанная стоимость хранения на 1000 пользователей, юридическое заключение. Финансовые приложения — вне трека навсегда.

## Три вещи, которые чаще всего убивают такие проекты

1. **Скоуп ползёт к «замене всех приложений».** Лекарство: формулировка цели в проверяемом виде и гейты выше. Каждый раз, когда кто-то говорит «но ведь цель — закрыть все потребности», возвращаемся к тесту клина.
2. **Wow вместо привычки.** Лекарство: проактивность и лента «Сегодня» — в фазе 3, а не «когда будет время». Продукт без ежедневной поверхности не доживает до фазы 4.
3. **Отсутствие измерений.** Лекарство: golden set и реплей заводятся в фазе 1, до того как появится что измерять. Иначе к неделе 8 никто не сможет сказать, стало лучше или хуже.
