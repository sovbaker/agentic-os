# S1–S3: что построено и что при этом выяснилось

Продолжение `07-s0-runbook.md`. Спринты S1, S2 и S3 из дорожной карты закрыты.

---

## S1 — Мозг

**Оркестратор разделён на роли.** Роутер определяет намерение, планировщик строит план и не имеет ни одного инструмента, исполнитель выполняет шаги узким набором, критик проверяет постусловия.

Критик — то, что отличает «сделано» от «вызвано без ошибки». Инструмент, вернувший `ok` при пустом результате, больше не считается успехом: это худший режим отказа, при котором метрики зелёные, а пользы нет.

**Движок задач.** План персистится как DAG шагов с зависимостями. Аренда через `FOR UPDATE SKIP LOCKED` плюс срок истечения — две реплики не возьмут одну задачу, упавший воркер не заблокирует её навсегда. Повторы с экспоненциальной выдержкой, ключи идемпотентности (перезапуск между вызовом и записью результата не создаёт второе письмо), компенсации в обратном порядке при отмене.

Задача живёт дольше HTTP-соединения: поток SSE — способ подсмотреть за исполнением, а не условие его работы.

**Защита от внедрения инструкций — архитектурная.** Всё, что инструмент помечает как недоверенное, проходит карантин в единственной точке, хранится отдельно от доверенного контекста и дальше живёт только как структура. Факты из недоверенных источников пишутся с источником `inferred`, поэтому по политике разрешения конфликтов они физически не могут перебить сказанное пользователем.

**Гибридный retrieval** оценивает факты по структуре, лексическому совпадению, свежести и важности — и достаёт из графа то, чего не хватает в запросе. «Займись визой» без названия страны теперь работает, если пользователь называл её раньше.

**Отмена исполнима.** В журнале хранится не флаг «обратимо», а то, чем именно откатывать: инструмент, аргументы и мини-аппа.

## S2 — Интерфейс

**Реестр вырос с 15 до 49 компонентов** и закрыт в обе стороны: в контракте ровно то, что клиент умеет рисовать. Компонент, объявленный, но не реализованный, раньше прошёл бы валидатор и приехал пользователю заглушкой. Теперь фикстура прогоняет все типы, тест падает при пропуске, а браузерная проверка снимает с неё скриншот в обеих темах.

**Компилятор мини-апп** выбирает источник в порядке: каталог → эвристика → модель. Порядок определяет экономику: чем чаще отвечает каталог, тем дешевле и качественнее продукт. Генерация остаётся разовой компиляцией версионируемого артефакта, а не вызовом на каждый рендер.

**Эвристика отталкивается от формы задачи, а не от темы.** Сравнение вариантов, отслеживание во времени и пошаговый план — три разных интерфейса, и перепутать их хуже, чем ошибиться в предметной области.

## S3 — Привычка

**Лента «Сегодня» — главный экран, а не чат.** Чат как главный экран означает, что вся инициатива на пользователе, а значит удержания не будет.

**Движок проактивности** разделён на сканер поводов, оценку уместности и доставку. Поводов всегда больше, чем уместных уведомлений, и решение «не беспокоить» принимается в одном месте: бюджет три в день, ночью молчим (кроме решения, которого ждут), дедупликация на уровне базы, обучение на реакции с намеренной асимметрией — игнор снижает вес класса сильнее, чем открытие поднимает, потому что цена лишнего уведомления измеряется удалением приложения.

**Коннекторы без единой внешней верификации.** Чтение почты у крупных провайдеров — restricted scope: аудит, деньги, недели. В обход: адрес для пересылки, который пользователь настраивает сам, и импорт `.ics`. Письмо идёт тем же путём, что и веб-поиск, — через карантин, потому что его содержимое пишет кто угодно.

**Онбординг без анкеты.** Архетипы кладут скелет графа с низкой уверенностью и источником `inferred` — опровергать легче, чем заполнять, и такой факт никогда не подаётся как знание. «Карта твоей жизни» показывает, что понято, с указанием источника у каждого факта: один тап превращает предположение в подтверждённый факт.

**Ассистированная передача** — то, что в MVP занимает место эмулятора: агент готовит всё, последний шаг человек делает одним тапом по ссылке с подставленными данными.

## Что нашлось при проверке

Все баги найдены прогоном, а не чтением кода.

| Что | Почему это важно |
|---|---|
| `\b` в JavaScript определена только по ASCII | все правила маршрутизации на русском молча не срабатывали |
| «визой» не покрывалось шаблоном | одна непокрытая падежная форма ломает маршрут, а внешне это «иногда не понимает» |
| Разбор срока останавливался на первом предлоге | «визу в Италию к октябрю» теряло срок целиком |
| Валидатор считал алиасы `repeat` ключами данных | резал корректные вложенные списки |
| Экран не мог опираться на данные от шагов задачи | пришлось объявить runtime-ключи явно, чтобы опечатка всё равно ловилась |
| Циклический импорт компилятора и реестра | падение на старте; чтение реестра сделано ленивым |
| `ON CONFLICT` по частичному уникальному индексу | нужен тот же предикат, иначе Postgres не сопоставляет ограничение |
| Дробный вес уезжал в `integer` | Postgres выводит тип параметра по первому использованию |
| **Повторное наблюдение плодило дубли фактов** | второй импорт того же `.ics` наполнял граф копиями и портил retrieval |

Последний — самый показательный: он не ломает ничего заметно, но со временем деградирует именно то, ради чего продукт существует.

## Проверки

```bash
npm run typecheck                        # 4 пакета
npm test                                 # 71 тест
npm run build:web && npm run verify:ui   # браузер, светлая и тёмная темы
```

Браузерная проверка прогоняет: онбординг с архетипами → карта жизни → фраза → SSE → мини-аппа → тап по чек-листу → действие на сервере → реестр из 49 компонентов. Падает при любой ошибке в консоли.

Интеграционные тесты идут на живом Postgres; без `DATABASE_URL` они пропускаются, а не падают.

## Что осталось за рамками

| Что | Почему |
|---|---|
| Нативный голос и пуши на устройстве | требуют сборки dev client, которой нет в этом окружении; веб-пути проверены, нативные обёрнуты в `try/catch` и деградируют |
| EventKit и CalDAV | порт `CalendarPort` готов, адаптеры подключаются без изменений выше |
| Golden set | собирается на реальных задачах при личном тестировании — по твоему решению |
| Векторный поиск | pgvector нет в этом Postgres; миграция пропускается штатно, retrieval деградирует до лексического |
| Веб-рендер и шаринг, MCP-клиент | вырезаны из первой версии осознанно (`06-roadmap.md`, §5) |
