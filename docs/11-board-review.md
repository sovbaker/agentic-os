# Ревью совета: приёмка S0–S4 и готовность к запуску

Три линзы — CEO, CPO, CTO — по одной кодовой базе. Метод собран из
публичных практик приёмки больших проектов: Google SRE Launch Coordination
Checklist (архитектура, надёжность, мониторинг, безопасность, выкатка,
рост, внешние зависимости), процесс Production Readiness Review, практика
Architecture Review Board (инспекция кода + реестр рисков + план
исправлений, а не «посмотреть глазами») и требования TestFlight к внешней
бете. Технический слой проверен независимым аудитом кода с подтверждением
каждого тезиса ссылкой file:line; десять заранее сформулированных гипотез
о блокерах подтверждались или опровергались по одной.

**Принимаемый объём:** 13 коммитов, ~25 000 строк, 7 миграций,
10 документов, 98 тестов, браузерная верификация в двух темах.

---

## Вердикт совета

**Архитектурно проект готов к запуску, операционно — нет.** Ядро — SDUI с
закрытым реестром, долгоживущие задачи с идемпотентностью и компенсациями,
карантин недоверенного контента, учёт расхода — спроектировано на уровне,
который обычно не встречается в MVP, и решения в нём совет одобряет без
оговорок. Но продукт ни разу не исполнялся в своих боевых условиях: ни
одного живого вызова Anthropic, ни одной сборки на устройство, ни одного
дня работы вне ноутбука. Между «всё зелёное в браузере» и «основатель
тестирует на своём iPhone» лежит ровно неделя работы, состав которой
известен точно и перечислен ниже. Главный систематический дефект один:
задачу одновременно ведут два драйвера исполнения, и это даёт двойные
побочные эффекты — чинить до первого личного теста.

## Линза CEO — стратегия и экономика

### Что одобрено

| Решение | Почему верно |
|---|---|
| РФ первым, глобал через порты (D1) | нигде не протёк в код: языковые правила, геокодинг, поиск — за адаптерами |
| Клин из пяти семейств (D2) | каталог покрывает все пять; scope creep за четыре спринта не случился — редкость |
| Эмулятор за research-гейтом (D3) | ни строчки кода на него не потрачено |
| Форвардинг вместо Gmail OAuth | обошли недели restricted-scope-аудита; работает с первого дня |
| TCFY как северная звезда | метрика уже считается и намеренно ломается, если продукт создаёт работу |
| Учёт расхода с первого дня | раздельные счётчики кэша, авто-истечение вводных тарифов, рубли и доллары не смешаны |

### Риски и дыры уровня CEO

1. **Экономика — до сих пор гипотеза.** Цель «≤25 ₽ на закрытую задачу»
   не проверена ни одним живым вызовом. Отдельно: вводная цена Sonnet 5
   ($2/$10) истекает **31.08.2026** — бета почти наверняка пойдёт по
   полной цене $3/$15. Код это учитывает автоматически, но юнит-экономику
   надо считать по полной цене. Действие: 20 живых задач → отчёт
   `npm run metrics` → сверка с 25 ₽.
2. **Дефолтный тариф глушит бету.** Все пользователи заводятся как
   `free`, а на free выключены генерация мини-апп и вся проактивность
   с пушами. Значит бета в текущей конфигурации тестирует продукт **без
   ретеншн-механики и без гейта G2**. Механизма стать Pro не существует
   ни за деньги, ни руками. Нужен бета-тумблер (все бета-юзеры = pro).
3. **Free-лимит считает и упавшие задачи.** 5 задач/мес считаются по всем
   `job` независимо от статуса: человек, у которого пять задач упало,
   потратил месяц и не получил ничего.
4. **Правовой контур не начат.** Фразы пользователя уходят в Anthropic
   (трансграничная передача), продукт хранит персональные данные жителей
   РФ (152-ФЗ), беты без политики конфиденциальности и согласия быть не
   должно. Плюс операционный вопрос оплаты Anthropic из РФ.
5. **Внешний критический путь.** Дорожная карта требовала запустить
   Apple Developer в день 1 — статус неизвестен совету. Если не начато,
   это самый календарно-длинный блокер (регистрация + первое Beta App
   Review). TestFlight-билды живут 90 дней — перевыкладка раз в квартал.

## Линза CPO — продукт и UX

### Что одобрено

Лента вместо чата, онбординг без анкеты, «делает с подтверждением» как
потолок доверия — и теперь этот потолок впервые **виден в интерфейсе**
(agentIntent с диффом, перечнем уходящего наружу и строкой «пока не
подтвердишь — ничего не отправляю»). Дизайн-переработка сняла все P0/P1
ревью Impeccable и закрепила их браузерным прогоном числами (44pt, 320px,
контрасты). Правило пустого прибора и «цвет только твоему ходу» — решения,
которые переживут генерацию, потому что исполняются рендерером.

### Разрывы, найденные приёмкой

1. **[P0] Ответ на уточняющий вопрос теряется.** `fire` передаёт payload,
   оболочка его выбрасывает (`App.tsx: case 'tool'`), на сервер уходят
   пустые args → `task.answer` отвечает «Нечего записывать». Флагманский
   цикл «ассистент спросил → ты ответил → задача продолжилась» разорван
   на клиентском слое. Основатель упрётся в это в первый день. ~2–4 ч.
   Вдогонку: при переоткрытии мини-аппы из ленты `jobId` не
   восстанавливается — `task.answer` упадёт и после фикса payload.
2. **[P0] Ассистент, который напоминает дважды.** Четыре независимых
   источника дублей: план сам ставит напоминание И кнопка в мини-аппе
   ставит его же; `reminderState` не пишется в `miniapp_state` (после
   переоткрытия кнопка снова активна); у `proactive_event` напоминаний
   нет дедуп-ключа; гонка двух драйверов (см. CTO) может исполнить шаг
   плана дважды. Для продукта, продающего «я держу твои дела», двойное
   напоминание — прямой удар по доверию.
3. **[P1] Два из четырёх состояний агентности — декорация.** `agentDid`
   наполняется реально (из журнала аудита), но `awaiting_who/since/usually`
   не пишет никто, а `before/after/discloses` у намерения захардкожены в
   пустые строки. Компоненты и данные под них есть, писателей данных нет:
   исполнитель должен ставить «жду ответа от X» при ожидании мира, а
   планировщик — заполнять дифф намерения. Пока этого нет, «Оттиск»
   отвечает на вопрос «чей ход» только в двух состояниях из четырёх.
4. **[P1] Экран не переживает выгрузку приложения.** iOS выгрузит
   приложение из фона — открытая мини-аппа и стек возврата пропали
   (персистится только токен). Casey-сценарий из ревью закрыт наполовину.
5. **[P2] Поиск — заглушка.** Деградация штатная (шаг опционален, задача
   продолжается), но «обогащение» мини-аппы фиктивно. Для личного теста
   терпимо, для беты нужен провайдер, доступный из РФ.
6. Гейты: G1 ждёт golden set (осознанно — собирает основатель), G2
   нетестируем, пока бета сидит на free (см. CEO-2).

## Линза CTO — архитектура и техника

### Что одобрено

- **Карантин** — лучшее место кодовой базы: недоверенный текст входит в
  систему через одну точку, наружу выходит только структурой, извлечение
  фактов идёт моделью без единого инструмента. Инвариант выдержан и для
  поиска, и для почты.
- **Durable jobs**: идемпотентность ключом, `FOR UPDATE SKIP LOCKED` +
  лизы с истечением, аудит и эффект в одной транзакции, компенсации в
  обратном порядке. Модель верная — подрывает её один дефект (ниже), а
  не дизайн.
- **Живой Anthropic-путь собран по контракту 2026 года** — аудит проверял
  это отдельно и опроверг опасения: `nullable` вместо `optional` в
  структурных схемах, `effort` и запас `max_tokens` на мышление гейтятся
  по модели, запрещённых параметров нет, расход пишется. Но он **ни разу
  не исполнялся** — первым действием после получения ключа должен быть
  смоук-прогон, а планировщику/композеру стоит дать стриминг (12k токенов
  без стрима — латентность на грани).
- Клиент деградирует вперёд: неизвестный компонент — заглушка с детьми,
  неизвестное SSE-событие игнорируется, сломанная каталожная аппа роняет
  деплой, а не пользователя.

### Дефекты

1. **[Высокая] Гонка двух драйверов исполнения.** SSE-поток ведёт задачу
   инлайново (`runJobToCompletion` без claim), и параллельно фоновый
   воркер каждую секунду подбирает задачи `running`. Между
   `runnableSteps` и `markStepRunning` нет гарда по статусу — долгий шаг
   (поиск 20 с, планирование Opus) заведомо длиннее тика, и воркер
   исполняет его второй раз. Идемпотентность спасает compose
   (`ON CONFLICT`), но не напоминания. Чинить до личного теста: либо
   инлайновый драйвер берёт lease, либо воркер не трогает задачи с
   активным потоком. 4–8 ч.
2. **[Средняя] `reminder.cancel` упомянут в манифесте и в плане, но не
   зарегистрирован** — компенсация при отмене задачи молча провалится.
   Рядом: `reversible: true` без объекта `compensation` — «обратимо,
   но нечем отменить».
3. **[Средняя] Продовой поверхности не существует.** Ни Dockerfile, ни
   хостинга, ни бэкапов; воркер и HTTP в одном процессе (для беты
   допустимо). TestFlight-клиенту нужен публичный HTTPS.
4. **[Средняя] Безопасность по мелочи, но всё в одну сторону:**
   `POST /v1/inbound/email` без `INBOUND_SECRET` вообще не
   аутентифицирован (отравление графа фактами низкого ранга + принудительный
   LLM-расход); rate limit и лимит тела отсутствуют на всех ручках, при
   том что `/v1/turns` жжёт токены; CORS `origin:'*'` с Authorization;
   девайс-токен в AsyncStorage вместо Keychain; погодный и календарные
   инструменты доступны с клиента без лимитов.
5. **[Низкая] CI нет вообще** — 98 тестов и typecheck гоняются руками.
   Час работы, чтобы каждый пуш проверял себя.
6. **[Низкая]** `EXPO_PUBLIC_API_URL` вшивается на этапе бандла, а
   `app.json.extra.apiUrl` мёртв — на телефоне API по умолчанию смотрит
   в сам телефон. Нужен eas-профиль с правильным URL.
7. **[Косметика]** `apps/mobile/dist/` закоммичен; миграции 001–002 не
   идемпотентны сами по себе (спасает трекинг применённых).

## Критический путь до запуска

### Личное тестирование (≈ неделя)

1. **Apple Developer** — если не начато, это пункт №1 по календарю.
2. **Сборка**: `eas.json` + projectId + плагин `expo-notifications` +
   профиль с боевым `EXPO_PUBLIC_API_URL` (0.5–1 день).
3. **Фикс payload** экшенов + восстановление `jobId` при переоткрытии
   (2–4 ч).
4. **Фикс гонки драйверов** (4–8 ч).
5. **Дев-тумблер plan=pro** (1 ч).
6. **Смоук живого ключа**: route/extract/plan/compose на пяти фразах,
   глазами в `llm_call` и стоимость (0.5 дня).
7. Персист `reminderState` + дедуп напоминаний (2–3 ч).

### Бета 20–30 человек (+1–2 недели)

8. Деплой: Dockerfile, managed Postgres с бэкапами, HTTPS, секреты
   (1–2 дня).
9. Пуши: `EXPO_PUSH_ENABLED`, APNs-credentials, проверка доставки (1 день).
10. `INBOUND_SECRET` обязателен + rate limit + body limit + CORS по
    списку + токен в SecureStore (совокупно ~1 день).
11. CI: typecheck + тесты + verify:ui на каждый пуш (2–4 ч).
12. Поисковый провайдер, доступный из РФ, вместо заглушки (0.5–1 день).
13. Домен + inbound-провайдер почты для форвардинга (0.5 дня).
14. Политика конфиденциальности + согласие + текст для Beta App Review.

### Чего сейчас НЕ делать

Биллинг, Android, веб-рендер, MCP-клиент, эмулятор, вынос воркера из
монолита, Temporal — всё это стоит в очереди правильно и очередь менять
не нужно.
