# S4: экономика, лимиты, приватность, измеримость

Продолжение `08-s1-s3-status.md`. Спринт S4 из дорожной карты закрыт — кроме
самой беты, которую нельзя написать кодом.

---

## Зачем этот спринт

До S4 продукт работал, но три вопроса о нём нельзя было задать честно:

1. **Сколько стоит закрытая задача?** В спеке стоит «≤ 25 ₽», но никто не считал.
2. **Что мы о человеке храним и как это забрать?** Ответ был «в базе», что не ответ.
3. **Правильно ли система понимает живую речь?** Тесты проверяли код, а не понимание.

S4 отвечает на все три — и превращает каждый из ответов в число, которое можно
показать.

---

## Учёт расхода

Каждый вызов модели пишется с разбивкой: вход, выход, **чтение кэша и запись
кэша отдельно**. Складывать их в один счётчик значит потерять ровно тот эффект,
ради которого кэш вводится: чтение дешевле входа вдесятеро, запись — дороже
в 1.25–2 раза.

Прайс сопоставляется по префиксу, поэтому `claude-haiku-4-5-20251001` и
`claude-haiku-4-5` — одна цена, и код об этом не знает. Вводная цена Sonnet 5
задана с датой окончания и **истекает сама**, без правки кода.

Неизвестная модель не считается в ноль молча: расход помечается и уходит в лог.
Иначе новая модель тихо исчезла бы из отчёта.

## Роутинг моделей по ролям

| Роль | Модель | Усилие |
|---|---|---|
| Роутер, экстрактор | `claude-haiku-4-5` | low |
| Сборка мини-аппы | `claude-sonnet-5` | medium |
| Планировщик | `claude-opus-5` | high |

Это первый рычаг экономики, а не микрооптимизация: маршрутизация короткой
фразы стоит копейки, и платить за неё по цене планирования незачем.

## Три дефекта, найденных при работе с API

Проверка адаптера по актуальной документации, а не по памяти, дала три
исправления — все три невидимы при чтении кода:

| Что было | Чем это ломается |
|---|---|
| `max_tokens: 1024` для планировщика на Opus 5 | у модели **мышление включено по умолчанию**, и `max_tokens` ограничивает мышление и ответ вместе — ответ обрывался посреди JSON тем чаще, чем сложнее задача |
| «Верни СТРОГО JSON» + чистка ```-обёртки регуляркой | разбор падал на осмысленно верном ответе; заменено на схему в `output_config.format` — формат теперь гарантирует API |
| `output_config.effort` без проверки модели | на Haiku 4.5 это 400: усилие появилось в поколении 4.6 |

Плюс точка кэширования: она ставится **только** если блок проходит минимум
модели (512 токенов у Opus 5, 1024 у Sonnet 5, 4096 у Haiku 4.5). Иначе в
промпте появляется разметка, которая ничего не экономит, — и ложная уверенность
в отчёте.

Кэшируется персональный контекст из графа: он одинаков для всех ролей хода и
редко меняется между ходами. Системная инструкция для этого слишком коротка,
а текст пользователя уникален каждый раз.

## Лимиты

Два разных ограничителя, и путать их нельзя.

**Продуктовый** — то, что видит пользователь: 5 задач в месяц на бесплатном
тарифе, генерация мини-апп и проактивность на Pro. Отказ в генерации не
оставляет без экрана: компилятор доходит до каталога, а каталог покрывает все
пять семейств клина.

**Предохранитель** — потолок расхода: 75 ₽ на free, 750 ₽ на Pro (половина цены
подписки). Он не рекламируется и в норме не достигается; срабатывание —
сигнал разработчику, а не оффер пользователю.

**Бюджет задачи** — 25 ₽ из архитектуры, §8. Проверяется между проходами
исполнителя, а не внутри шага: смысл в том, чтобы не начать следующий круг,
а не оборвать начатое действие на середине. Перерасход переводит задачу в
`waiting_user`, а не в `failed`: это не ошибка исполнения, а решение,
которое принимать человеку.

## Приватность

Экран «Данные и приватность» — **серверный UISpec**, а не нативный экран.
На экране про доверие формулировки правятся чаще всего, и каждая правка не
должна стоить релиза в App Store.

На экране видно: сколько фактов, эпизодов, задач и действий; **сколько писем
и страниц лежит в карантине — отдельной строкой**; тариф и расход в рублях с
честной подписью «это наши расходы на твои задачи, а не счёт тебе».

**Выгрузка** — двенадцать таблиц, включая журнал расхода. Карантина в ней нет
намеренно: там сырой текст писем и страниц, то есть данные третьих лиц,
попавшие к нам как вложение. Отдавать их в «твои данные» неверно и по смыслу,
и по закону.

**Удаление** настоящее, каскадом, а не флаг. Запись о запросе переживает
самого пользователя (`ON DELETE SET NULL`) — иначе единственное доказательство
того, что удаление состоялось, исчезает вместе с удалением.

## Метрики

`npm run metrics` печатает то, на что смотрят раз в неделю перед интервью с бетой.

**TCFY** считается как «задача дошла до `done` **и** по ней есть хотя бы одно
действие в журнале». Второе условие отсеивает то, что выглядит успехом в
статусах, но ничего не сделало в мире.

Рядом — доля задач, потребовавших вопроса пользователю. Она растёт ровно
тогда, когда продукт начинает создавать работу вместо того, чтобы её забирать,
и это единственная метрика, которую хочется видеть падающей.

Экономика показывает медиану и **p90** на закрытую задачу: экономику ломает
хвост, а не среднее. И долю входа, пришедшую из кэша, — прямой эффект
оптимизации.

## Эвалы

С AI-агентом объём кода перестал быть узким местом. Узким стала **проверка
правильности** — и эвалы это то, чем заменяется код-ревью: не «код выглядит
разумно», а «на сорока реальных фразах решения не поехали».

Оснастка готова целиком: формат случая, загрузчик JSONL, сравнение, отчёт,
прогон с кодом возврата для CI и гейтом G1. Прогон **без побочных эффектов** —
задача не создаётся, инструменты не вызываются; иначе один прогон набора
отправил бы сорок писем.

**Набор случаев пуст, и это правильное состояние.** Примеры, придуманные тем
же человеком, который писал правила маршрутизации, проверяют совпадение автора
с самим собой. Настоящий набор собирается на реальных фразах — по твоему
решению, при личном тестировании.

Для этого есть записывающий режим: `RECORD_EVALS=1` дописывает заготовку на
каждый ход, уже заполненную тем, что система решила. Поправить надо только то,
где она ошиблась. Заготовка помечена `reviewed: false` и **в прогон не идёт**,
пока её не разметили: иначе набор закрепит текущее поведение как правильное и
перестанет ловить регрессии ровно тогда, когда начнёт врать.

Ещё одно решение из той же логики: пустой набор печатает «набор пуст», а не
«100% пройдено». `0/0` — это не успех, это отсутствие проверки.

## Что нашлось при проверке

| Что | Почему это важно |
|---|---|
| `privacy_request` каскадом уносилась вместе с пользователем | запись об удалении исчезала в момент удаления — то есть доказательства не оставалось никогда |
| `keyValue` принимает список пар, а не `label`/`value` | спека проходила валидатор и приезжала пользователю пустым блоком; поймано браузерным прогоном, а не типами |
| Валидатор потребовал `confirm` у `privacy.delete` | необратимое действие без текста подтверждения не должно доезжать до клиента — сработала защита, написанная в S2 |

Третья строка — единственный приятный случай: баг не дошёл до прогона, потому
что его поймала проверка, встроенная раньше.

## Проверки

```bash
npm run typecheck                        # 5 пакетов
npm test                                 # 98 тестов
npm run evals                            # golden set (пуст до сбора)
npm run metrics                          # продуктовые метрики
npm run build:web && npm run verify:ui   # браузер, светлая и тёмная темы
```

Браузерная проверка теперь включает экран приватности в обеих темах: карантин
отдельной строкой, расход в рублях, кнопка удаления на месте.

## Гейты

- **G1** (качество планировщика) — оснастка готова, порог задаётся `EVALS_GATE`, набор собираешь ты.
- **G2** (мини-аппа против текста) — `npm run metrics` показывает разбивку по origin и долю каталога.
- **G3** (TCFY ≥ 3) — считается и проверяется автоматически; нужна бета.

Осталось нетехническое: 20–30 человек из целевого сегмента и еженедельные
интервью. Это единственная часть S4, которую нельзя написать кодом.
